Local development infrastructure

One shelf.
Every project.

Stop running a Postgres per repository. Start the services once — every project on your machine reaches them by hostname, holding its own database, user and generated password.

Quick start Read the docs

One command per project

shelf setup creates the database, the user, the vhost and the bucket, generates a password for each, records them in the registry, and prints a block you paste straight into the project’s .env.

Reprint it any time with shelf credentials <app>. Nothing is stored in your shell history. 

$ shelf setup billing -s postgres,redis

✓ postgres  database billing, user billing
✓ redis     ACL user billing, prefix billing:

# paste into billing/.env
DATABASE_URL=postgres://billing:•••@postgres:5432/billing
REDIS_URL=redis://billing:•••@redis:6379

Every app is walled off

No project holds another’s credentials, and no project holds a superuser.

Service Reached at What an app gets
PostgreSQL postgres:5432 Dedicated database and user
Redis redis:6379 ACL user, restricted to its key prefix
RabbitMQ rabbitmq:5672 Dedicated vhost and user
MongoDB mongodb:27017 Dedicated database and user
S3 — MinIO or AIStor aistor:9000 Dedicated bucket and access key
SignOz signoz-otel-collector:4317 Its own service.name and attributes

Quick start

One command clones the repository, builds the binaries and starts the core stack. No Go toolchain? It builds inside Docker instead. 

$ curl -fsSL https://raw.githubusercontent.com/IvanMicai/infra-shelf/main/scripts/install.sh | bash

or, already cloned

$ make quickstart   # init + build + up
$ ./shelf setup myapp -s postgres,redis,rabbitmq,mongodb

Change the default passwords in .env before exposing anything beyond your machine — see the security policy.
